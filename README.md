# DSH Game Player

面向 **DeepSeek Harness** 的 Windows 插件：为模型提供截图、窗口绑定和受审批控制的键鼠操作，并提供桌面键鼠显示与 Live2D 桌宠。

> **这不是独立游戏程序，也不是通用的自主游戏代理。** 插件依赖 DeepSeek Harness 提供工具注册、附件、审批和客户端 UI 服务。直接运行 `node index.js` 不会启动可用的宿主。项目不包含角色模型、贴图、动作或音频。

当前版本 **0.3.13**：截图独立通道、轻量状态刷新与设置页精简（真实游戏及桌面 GPU 帧时间仍需实机验收）。分发包与校验文件见 [Releases](https://github.com/sjkk16/dsh-game-player/releases/latest)，完整变更记录见 [CHANGELOG.md](CHANGELOG.md)。

## 功能

**模型工具**（由宿主注册，供会话中的模型调用）：

| 工具 | 作用 |
| --- | --- |
| `game_screen` | 按需获取屏幕或已绑定窗口的图像 |
| `game_window` | 列出窗口、显式绑定/解绑目标并查询状态；不自动抢夺窗口焦点 |
| `game_input` | 执行鼠标和键盘动作；默认 `requireApproval: true`，真实输入必须经过宿主审批 |
| `game_macro` | 保存和管理本地动作模板；不要在模板中保存凭据或私人信息 |
| `game_watch` | 仅保留兼容接口；**自动画面变化通知已永久停用**，请按需调用 `game_screen` |

**桌面显示**：键鼠面板、Live2D 模型库（ZIP 导入、删除、动作与显示设置）、控制自适应模式、聊天人格档案（默认关闭）。

## 安全边界

- 真实键鼠输入会影响本机正在运行的程序。请先绑定正确窗口、保留审批，并在不含敏感内容的环境中使用。
- 插件不修改游戏、不提权、不注入游戏进程、不绕过反作弊。Raw Input 操作者识别不是身份认证，无法可靠鉴别硬件宏或驱动模拟。
- 角色模型由用户自行准备，需遵守模型作者的授权。

## 安装（使用分发包）

### 前置条件

| 依赖 | 说明 |
| --- | --- |
| Windows | 桌面项目目标框架 `net10.0-windows10.0.17763.0` |
| .NET 10 Desktop Runtime | 含 Windows Desktop/WPF/WinForms 框架；Release 为框架依赖型部署，不自带 .NET 运行时 |
| Microsoft Edge WebView2 Runtime | Release 中的 WebView2 SDK DLL 不能替代 Runtime |
| Windows PowerShell | 输入桥默认使用系统自带的 Windows PowerShell |
| Node.js + pnpm | 依赖安装及命令行检查；需支持当前 pnpm 锁文件格式 |

.NET 与 WebView2 请从 Microsoft 官方渠道安装。目录中的桌面 EXE/DLL 只是插件的显示组件，不替代 DeepSeek Harness。

### 步骤

1. 从 [Releases](https://github.com/sjkk16/dsh-game-player/releases/latest) 下载 `dsh-game-player-<版本>.zip` 及配套 `.sha256` 校验文件。
2. 校验哈希一致后再解压：

   ```powershell
   Get-FileHash -Algorithm SHA256 dsh-game-player-0.3.13.zip
   ```

3. 在解压出的 `dsh-game-player` 目录安装生产依赖：

   ```powershell
   pnpm install --prod --frozen-lockfile
   ```

4. 按所用 DeepSeek Harness 版本提供的本地插件/bundle 加载方式选择此解压目录。包标识为 `@local/dsh-game-player`，插件行标识为 `game-player`；入口和补丁已由包清单声明。
5. 保留 `cordis.patch.yml` 中的 `requireApproval: true`。需要 Live2D 时，在模型的模型管理界面导入你拥有使用权限的模型。

**不要改变运行时相对目录**：`runtime/desktop-<版本>-performance/` 必须与插件入口处于同一解压根目录下。ZIP 不包含依赖目录，依赖安装仍是必要步骤。

更新插件版本后，请完全退出 Harness（包括托盘后台进程）再重新启动，确保宿主与已运行的桌面进程都加载最终资源。

## 从源码构建

```powershell
git clone https://github.com/sjkk16/dsh-game-player.git
cd dsh-game-player
npm test
npm run test:pack
# 要在宿主中加载源码插件，再安装生产依赖：
pnpm install --prod --frozen-lockfile
```

源码仓库不包含预编译运行时、Live2D SDK 或模型；若要直接使用现成运行时，优先下载 Release 的完整分发包。

### 构建 Live2D 桌面运行时

需要 **.NET 10 SDK**（不是仅 Desktop Runtime）、完整开发依赖（`pnpm install --frozen-lockfile`）、可用的 NuGet 依赖源，以及另行取得的官方 **Cubism SDK for Web 5-r.5**。构建脚本不会自动下载 Live2D SDK 或角色模型；.NET restore 可能访问 NuGet。

- 官方 SDK ZIP：`CubismSdkForWeb-5-r.5.zip`，SHA-256 为 `67064a7fb1812cf502f5c4a03bfe12cc638c75a621bb4acf06bb28763df06ba0`。将 ZIP 及同名解压目录放在同一父目录（默认 `.qa/sdk/`）。
- 脚本会验证 Core 及框架文件的固定哈希，不能以其他 SDK 版本替代。先阅读 SDK 原始许可证和第三方声明；使用和发布授权由用户自行负责。

```powershell
pnpm run build:live2d -- --sdk "D:\SDKs\CubismSdkForWeb-5-r.5"
pnpm test
pnpm run test:release
```

生成的桌面网页、构建缓存和 `runtime/` 均被 Git 忽略。构建成功不等于渲染或真实输入验收。构建脚本会在写入前拒绝占用中的输出：先停止桌宠显示，或将 `DSH_DESKTOP_OUTPUT` 指向本项目 `.qa` 下的隔离目录。

### pnpm 构建脚本策略

部分 pnpm 版本可能阻止 `esbuild` 的安装后脚本并要求手动批准。不要自动放开全部依赖的脚本权限；只有在核对依赖来源、确实要构建时，再按 pnpm 提示批准 `esbuild`。本项目的静态检查不依赖它，可直接使用 `npm test` 和 `npm run test:pack`，无需先安装任何依赖。

## 检查命令与验证范围

| 命令 | 检查内容 |
| --- | --- |
| `npm test` / `pnpm test` | JS/MJS 语法、字面量本地引用、JSON、必需源码、常见敏感内容模式及内存中的打包清单回归；不加载插件、不截图、不发送输入 |
| `npm run test:pack` | npm 实际打包清单、必需源码及禁止文件；兼容纯源码目录和含当前版本运行时的目录，拒绝混入其他运行时版本；不验证运行时完整性 |
| `npm run test:release` | 含运行时的打包预览、托管/原生依赖、13 个着色器、许可证、资源一致性及已记录的构建哈希 |
| `npm run test:renderer` / `test:renderer-native` | 渲染器生命周期源码约束与宿主警告隔离回归；29 项原生生命周期自检（不初始化浏览器、不安装输入钩子） |

## 本地存储与模型管理

- 存储目录缺失时自动补建；本地目录链接的目标缺失时，会补建目标并保留链接。设置、模板和模型索引文件在首次保存时生成，不覆盖损坏的现有文件；权限不足、循环链接或非本地链接目标会明确报错。
- **添加 ZIP 模型**：设置页仅在"我的桌宠"提供"添加 ZIP 模型"入口。ZIP 必须包含 `.model3.json` 及配套资源；确认后加入模型库，不自动切换当前桌宠。如提示需要重新加载插件，请完全退出 DeepSeek Harness（包括托盘后台进程）后重新启动。
- **删除模型**：可以删除库里最后一个或当前选中的模型。删除当前模型会先解除选择、停止旧显示并退回键鼠视图；无需存在默认示例模型，也不会自动换成其他模型。项目不自带示例模型，未选择模型时保持键鼠显示，不自动加载不存在的默认目录。删除只针对模型库管理的副本，不修改原始导入文件；仍被其他条目共用的资源包会保留。面板停用时也可删除，正在加载、预览或播放动作时须先结束该操作；删除按钮要求确认。
- **作者授权水印**：仅对原授权清单中 moc 文件哈希完全匹配、参数定义一致且运行时验证通过的清宵和达妮娅生效；模型名称或文件名不能代替授权。在模型库下方的"作者授权水印"区域，可选择"隐藏水印"或"恢复作者默认"；其他模型、未通过验证的模型不会出现可编辑开关。动作、预览、加载、窗口调整或未确认的输入状态下不可修改；取消、超时或验证失败时不提交设置。只使用原有受限参数开关，不改写模型文件、网格、纹理或其他资源；缺失的隐藏记录按作者默认处理。

## 控制自适应模式

在"桌宠管理"中选择"控制自适应模式"，并显示桌宠后，键盘或 Live2D 将只读映射整个桌面的键鼠操作。上方持续显示最后识别的"人控制"或"AI控制"；空闲、切换界面不会清除，重启后等待首次识别，不保存操作者历史。

- "人"指 Raw Input 键盘设备事件和非注入鼠标事件；Raw Input 注册失败时，键盘降级为非注入钩子事件。"AI"仅指本插件已确认的真实输入；其他软件注入使用独立未知提示，不能可靠识别硬件宏、驱动模拟或实际操作者身份。
- 此模式不会中断 AI、修改审批或释放机制，不读取输入文本或剪贴板、不保存按键历史。隐藏桌宠、关闭模式、锁屏或退出时停止只读监听。
- "显示模型下方文字"控制普通底部说明，默认开启。关闭时上方操作者和安全警告仍显示，不改变模型大小、位置或作者授权水印。

### 按需诊断

owner 管理接口 `gamePlayerOverlay.getState()` 的返回值包含可选 `inputDiagnostics`：`controller.human/ai/merged/sent`、`native.observer`（keyboardBackend、注册错误码、事件计数与队列丢弃）、`native.desktop`、`native.renderer` 的计数、序号、按键数量和时间间隔。数据只在内存中保留计数与最后状态，不含按键身份、输入文本或操作历史，不自动落盘。查询不会启动尚未运行的桌宠；旧运行时不支持时 native 为 null。零事件计数也可能只是当前没有输入，不能单凭空闲判定监听故障。

## 聊天人格档案

设置页新增"人格"标签页。默认关闭，不创建示例档案。人格只改变交流风格和角色表现，不修改工具权限、键鼠审批或技术准确性，也不会新增聊天服务、长期记忆、自动成长或桌宠动作联动。

1. 点击"新建"，填写档案名称（最多 80 字符）和自由文本人格描述（最多 8,000 字符），两者都不能只包含空白。可以先打开"启用聊天人格"再新建，也可以保持关闭直接新建和保存；新建/保存不会自动打开开关或选择当前人格。
2. 点击"保存"提交草稿。点击列表中的档案只切换编辑对象，不切换聊天人格。未保存时离开或删除草稿，可以选择保存并继续、放弃修改并继续或取消。
3. 对已保存且没有未保存修改的档案，点击"使用此人格"同时选中并启用它。保存正在启用的档案后，下一次模型请求使用新内容；已经进行中的请求和历史消息不会被改写。
4. 保存档案后即可直接打开顶部开关，无需先点击"使用此人格"。重新启用时优先沿用之前的当前人格；开关旁会显示将启用的档案名称，且只启用保存版本，不会保存或使用草稿。关闭后仍保留档案和当前选择；删除当前人格会关闭功能并清空当前选择。保存失败会保留草稿；另一页面改动同一档案时，不会静默覆盖你的草稿。

**作用范围与隐私**：同一 Harness 配置下的聊天共用当前人格，而不是每个会话独立选择。档案通过宿主的配置表单持久化，并随正常请求发送给现有模型提供方；请勿填写密码、密钥等秘密。角色背景属于虚构设定，不能当作真实经历、记忆、能力或已执行操作的证据。人格描述中的变量占位符保留原文，不进行宿主变量插值。

**兼容性**：首次安装这项功能后需重新加载插件，使后台配置与客户端页面同步；如果宿主仍使用旧后台，请完全退出 Harness（包括托盘进程）后重启。人格切换本身无需重启插件或桌宠。需要宿主系统提示词服务；缺少该服务时其他插件功能仍可使用，完整系统提示词覆盖可能使附加人格不生效，本插件不会强制覆盖它。
