# DSH Game Player

面向 **DeepSeek Harness** 的 Windows 插件：为模型提供截图、窗口绑定和受审批控制的键鼠操作，并提供桌面键鼠显示及 Live2D 模型管理。

> **这不是独立游戏程序，也不是通用的自主游戏代理。** 插件依赖 DeepSeek Harness 提供工具注册、附件、审批和客户端 UI 服务。直接运行 `node index.js` 不会启动可用的宿主。项目不包含角色模型、贴图、动作或音频。

当前版本：**0.3.13**（截图独立通道、轻量状态刷新与设置页精简；真实游戏及桌面 GPU 帧时间仍需实机验收）。本版本源码已上传 GitHub，Release 附含预编译运行时的完整分发包与 SHA-256 校验文件。

- 截图、窗口查询和截图指纹清理使用按需启动的独立只读 PowerShell 进程，不初始化输入账本或监听，不接受输入命令。输入、审批、窗口绑定、故障锁和释放看门狗保持独立。
- 每次仍采集新画面。未变化且没有强制图像需求时跳过缩放、JPEG 编码和 Base64；首次截图、强制截图及附件失败后的重试仍返回新图。原 64×36 指纹算法迁入 C#，画质、分辨率与 3% 阈值不变。
- 设置页默认每秒调用 owner-only 的 `gamePlayerOverlay.getSummary()`；配置、模型库与资源检查最多每五秒合并一次。修改命令仍严格验证资源证明和原生安全状态。旧宿主只对“方法不存在”回退 `getState()`，不重放修改命令。

- 可见时保持原 60 FPS 调度；隐藏时不绘制。每帧共享一次状态投影，画布尺寸仅在尺寸/DPI 变化时读取。

完全退出 Harness（包括托盘）并重新启动，确保宿主与已运行桌面进程都加载最终资源。原 0.3.12、0.3.6 运行时未删除；本次也未终止正在运行的插件。

开发副本可执行 `npm run test:performance`。合成截图、界面与渲染测试的范围、性能数字及回退方法见本地 `OPTIMIZATION-REPORT-0.3.13-2026-11-17.md`，不代表游戏实机验收。诊断仅保留内存中的最多 128 个耗时样本，不保存画面、输入文本、按键身份或持久运行日志；宿主附件服务的真实耗时需要在 Harness 中按需测量。

## 聊天人格档案

设置页新增“人格”标签页。默认关闭，不创建示例档案。人格只改变交流风格和角色表现，不修改工具权限、键鼠审批或技术准确性，也不会新增聊天服务、长期记忆、自动成长或桌宠动作联动。

1. 可以先打开“启用聊天人格”再新建，也可以保持关闭直接新建和保存；新建/保存不会自动打开开关或选择当前人格。空档案时也能打开开关，但没有选中人格时聊天不会改变。点击“新建”，填写档案名称和自由文本人格描述；名称最多 80 字符，描述最多 8,000 字符，两者都不能只包含空白。
2. 点击“保存”提交草稿。点击列表中的档案只切换编辑对象，不切换聊天人格。未保存时离开或删除草稿，可以选择保存并继续、放弃修改并继续或取消。
3. 对已保存且没有未保存修改的档案，点击“使用此人格”同时选中并启用它。保存正在启用的档案后，下一次模型请求使用新内容；已经进行中的请求和历史消息不会被改写。
4. 保存档案后即可直接打开顶部开关，无需先点击“使用此人格”。重新启用时优先沿用之前的当前人格；尚未选择过当前人格时，使用正在编辑的已保存档案，否则使用列表第一份已保存档案。开关旁会显示将启用的档案名称，且只启用保存版本，不会保存或使用草稿。没有已保存或选中的人格时，开关仍可打开，页面显示“已开启，尚未选择人格”；保存后点击“使用此人格”才会应用。关闭后仍保留档案和当前选择。删除当前人格会关闭功能并清空当前选择。保存失败会保留草稿；另一页面改动同一档案时，不会静默覆盖你的草稿。

**作用范围与隐私：** 同一 Harness 配置下的聊天共用当前人格，而不是每个会话独立选择。档案通过宿主的配置表单持久化，并随正常请求发送给现有模型提供方；请勿填写密码、密钥等秘密。角色背景属于虚构设定，不能当作真实经历、记忆、能力或已执行操作的证据。人格描述中的变量占位符保留原文，不进行宿主变量插值。

**兼容性：** 首次安装这项功能后需重新加载插件，使后台配置与客户端页面同步；如果宿主仍使用旧后台，请完全退出 Harness（包括托盘进程）后重启。人格切换本身无需重启插件或桌宠。需要宿主系统提示词服务；缺少该服务时其他插件功能仍可使用，完整系统提示词覆盖可能使附加人格不生效，本插件不会强制覆盖它。

## 本地存储与模型添加

- 存储目录缺失时自动补建；若本地目录链接的目标缺失，会补建目标并保留链接。设置、模板和模型索引文件仍在首次保存时生成，不覆盖损坏的现有文件。权限不足、循环链接或非本地链接目标会明确报错。
- 设置页仅在“我的桌宠”提供“添加 ZIP 模型”入口。ZIP 必须包含 `.model3.json` 及配套资源；勾选并确认后加入模型库，不自动切换当前桌宠。单独模型文件及文件夹的旧内部接口仅保留兼容，不再作为设置入口。

如果添加 ZIP 时提示需要重新加载插件，请**完全退出 DeepSeek Harness（包括托盘后台进程）后重新启动**。新客户端会核对后台是否支持 ZIP 专用指令，不向旧后台发送未支持的指令，也不会回退到会切换桌宠的旧导入流程。

## 功能与安全边界

- `game_screen`：按需获取屏幕或已绑定窗口的图像。
- `game_window`：列出窗口、显式绑定/解绑目标并查询状态；不自动抢夺窗口焦点。
- `game_input`：执行鼠标和键盘动作；默认 `requireApproval: true`，真实输入必须经过宿主审批。
- `game_macro`：保存和管理本地动作模板；不要在模板中保存凭据或私人信息。
- 桌面显示：键鼠面板、Live2D 模型导入、动作和显示设置等。
- `game_watch` 只保留兼容接口；**自动画面变化通知已永久停用**，请按需调用 `game_screen`。

真实键鼠输入会影响本机正在运行的程序。请先绑定正确窗口、保留审批，并在不含敏感内容的环境中使用。角色模型由用户自行准备，需遵守模型作者的授权。

## 使用预编译分发包

### 前置条件

- Windows；桌面项目目标框架为 `net10.0-windows10.0.17763.0`。
- 能加载本地插件/bundle 的 **DeepSeek Harness**，并提供工具、附件和所需客户端 UI 服务。
- **.NET 10 Desktop Runtime**（包含 Windows Desktop/WPF/WinForms 框架）。Release 使用框架依赖型部署，不自带 .NET 运行时。
- **Microsoft Edge WebView2 Runtime**。Release 中的 WebView2 SDK DLL 不能替代 WebView2 Runtime。
- Windows PowerShell。输入桥默认使用系统自带的 Windows PowerShell。
- Node.js（带 npm）和 pnpm，用于依赖安装及命令行检查。请使用支持当前 pnpm 锁文件格式的版本。

.NET 与 WebView2 请从 Microsoft 官方渠道安装。目录中的桌面 EXE/DLL 只是插件的显示组件，不替代 DeepSeek Harness。

### 安装步骤

1. 本目录已包含源码和本地构建的运行时，可通过宿主的本地插件入口加载；若另行使用 ZIP 分发，先解压并核对对应的 SHA-256 校验文件。
2. 在 PowerShell 中用 `Get-FileHash -Algorithm SHA256` 计算 ZIP 的哈希，与校验文件比较后再解压。
3. 在解压后的 `dsh-game-player` 目录安装生产依赖：

   ```powershell
   pnpm install --prod --frozen-lockfile
   ```

4. 按所用 DeepSeek Harness 版本提供的本地插件/bundle 加载方式，选择此解压目录。包标识为 `@local/dsh-game-player`，插件行标识为 `game-player`；入口和补丁已由包清单声明。
5. 保留 `cordis.patch.yml` 中的 `requireApproval: true`。不同宿主版本的安装入口可能不同；本项目不假定未经验证的宿主 CLI 命令。
6. 需要 Live2D 时，在插件的模型管理界面导入你拥有使用权限的模型。模型文件不会随项目分发。

**不要改变运行时相对目录：** `runtime/desktop-0.3.13-performance/` 必须与插件入口处于同一解压根目录下。ZIP 不包含依赖目录，依赖安装仍是必要步骤。

### 构建 Live2D 桌面运行时

需要 **.NET 10 SDK**（不是仅 Desktop Runtime）、完整开发依赖（使用 `pnpm install --frozen-lockfile` 安装）、可用的 NuGet 依赖源，以及另行取得的官方 **Cubism SDK for Web 5-r.5**。构建脚本不会自动下载 Live2D SDK 或角色模型；.NET restore 可能访问 NuGet。

- 官方 SDK ZIP：`CubismSdkForWeb-5-r.5.zip`。
- ZIP SHA-256：`67064a7fb1812cf502f5c4a03bfe12cc638c75a621bb4acf06bb28763df06ba0`。
- 将 ZIP 及同名解压目录放在同一父目录；也可使用默认位置 `.qa/sdk/`。
- 脚本还会验证 Core 及框架文件的固定哈希，不能以其他 SDK 版本替代。
- 先阅读 SDK 原始许可证和第三方声明；用户自行负责适用的使用和发布授权。

```powershell
pnpm run build:live2d -- --sdk "D:\SDKs\CubismSdkForWeb-5-r.5"
pnpm test
pnpm run test:release
```

上例应同时存在 `D:\SDKs\CubismSdkForWeb-5-r.5.zip`。生成的桌面网页、构建缓存和 `runtime/` 均被 Git 忽略。构建成功不等于渲染或真实输入验收。

### pnpm 构建脚本策略

部分 pnpm 版本可能阻止 `esbuild` 的安装后脚本并要求手动批准。不要自动放开全部依赖的脚本权限；只有在核对依赖来源、确实要构建时，再按 pnpm 提示批准 `esbuild`。本项目的静态检查不依赖它，可直接使用 `npm test` 和 `npm run test:pack`，无需先安装任何依赖。

## 控制自适应模式（0.3.10 引入，0.3.11 扩展）

在“桌宠管理”中选择“控制自适应模式”，并显示桌宠后，键盘或 Live2D 将只读映射整个桌面的键鼠操作。上方持续显示最后识别的“人控制”或“AI控制”；空闲、切换界面不会清除，重启后等待首次识别，不保存操作者历史。标识不表示仍在持续输入。

“人”指 Raw Input 键盘设备事件和非注入鼠标事件；Raw Input 注册失败时，键盘降级为非注入钩子事件；“AI”仅指本插件已确认的真实输入；其他软件注入使用独立未知提示，不能可靠识别硬件宏、驱动模拟或实际操作者身份。此模式不会中断 AI、修改审批或释放机制，不读取输入文本或剪贴板、不保存按键历史。隐藏桌宠、关闭模式、锁屏或退出时停止只读监听。

“显示模型下方文字”控制普通底部说明，默认开启。关闭时上方操作者和安全警告仍显示，不改变模型大小、位置或作者授权水印。

安全检查：

```powershell
node scripts/adaptive-regression.mjs
```

此检查使用隔离设置和合成事件，不安装真实全局监听、不发送真实键鼠；实际显示仍需重启宿主后由用户手动验收。

## 全屏键盘兼容（本地 0.3.11）

针对《明日方舟：终末地》中“全屏长按无响应、窗口化恢复”的报告，本版增加 Windows Raw Input 后台键盘接收。它使用隐藏消息窗口和 RIDEV_INPUTSINK，不依赖桌宠获得焦点，也不要求游戏未注册 Raw Input。注册成功后，人类键盘只从该通道更新；旧钩子保留鼠标和注入来源识别，注册失败时降级。设备移除、锁屏、隐藏或停用会按原生命周期清理观察状态。

AI 操作显示仍以插件已确认的输入账本为准，不需要被 Raw Input 再捕获。审批、故障锁、释放确认、短按余光与模型绑定不变。Raw Input 不是操作者身份认证，无法可靠鉴别硬件宏或驱动模拟；本插件不修改游戏，不提权、不注入游戏进程，也不绕过反作弊。

**安装使用：**退出并重新打开 DeepSeek Harness，加载本开发副本，在桌宠管理中保留“控制自适应模式”。当前加载目录为 `runtime/desktop-0.3.13-performance`，旧 0.3.12 与 0.3.6 运行时保留。构建脚本会在写入前拒绝占用中的输出；后续开发应先停止桌宠，或将 DSH_DESKTOP_OUTPUT 指向本项目 .qa 下的隔离目录。

### 按需诊断

现有 owner 管理接口 `gamePlayerOverlay.getState()` 的返回值新增可选 `inputDiagnostics`，不增加公开工具参数：

- `controller.human / ai / merged / sent`：进入插件、状态合并与写入桌面管道的计数、序号、按键数量和时间间隔。
- `native.observer`：keyboardBackend（raw-input / hook）、注册错误码、原始／钩子事件计数、队列丢弃数及最新事件间隔。
- `native.desktop`：桌面收到与转发到渲染器的状态序号和按键数量。
- `native.renderer`：渲染器收到／应用的状态序号，以及键盘参数是否绑定、冻结与当前参数值。

数据只在内存中保留计数与最后状态，不包含按键身份、输入文本或操作历史，不自动落盘。查询不会启动尚未运行的桌宠；旧运行时不支持时 native 为 null。零事件计数也可能只是当前没有输入，不能单凭空闲判定监听故障。

### 验证命令与待验收项

~~~powershell
pnpm test
pnpm run test:fullscreen
pnpm run test:native-keyboard
pnpm run test:native-keyboard -- --receiver-smoke
pnpm run test:pack
pnpm run test:release
~~~

默认回归使用合成事件和隔离设置；原生自检不安装钩子、不发送输入。receiver-smoke 会短暂创建隐藏 Raw Input 接收器，检查后台注册、焦点与清理，收到的事件直接丢弃，不记录按键。

**尚需用户实机验证：**同一模型下对比《终末地》的窗口、原故障全屏与无边框模式（若提供）；长按 W/A、组合键、松开及反复切换，确认模型响应和游戏原有输入不受影响。游戏内 AI 测试仍需明确审批。自动检查与后台注册成功不等于游戏兼容已确认。

## WebView2 生命周期修复（0.3.12，2026-11-12）

针对“UtilityProcessExited 后，WebView2CompositionControl 在尺寸变化时发生 D3D 纹理空引用并退出”的报告：

- 可恢复的辅助／GPU／沙箱／子框架进程退出只记录警告；主浏览器、主渲染器退出或无响应、未知类型仍安全降级到键鼠面板，不自动重启。
- 释放前在 UI 线程关闭尺寸回调门、解除命名订阅并退出布局，再释放控件；正常关闭、故障与初始化晚到共用清理路径。
- 只处理堆栈明确来自 WebView2 D3D 纹理创建的空引用，通过 Dispatcher 延后降级；无关异常不屏蔽。
- 警告补充 kind、Reason、ExitCode 与长度受限的 ProcessDescription，不新增持久运行日志。

原生自检 29 项、真实 WebView2 隐身检查 19 项通过；后者验证降级后的窗口存活、释放后尺寸更新、重复／晚到清理及另一独立浏览器环境不受影响。现有纯逻辑回归 86/86 通过。完整记录见 [修复报告](WEBVIEW2-LIFECYCLE-REPORT-0.3.12-2026-11-12.md)。

这些检查不是原游戏场景的复现或可见桌宠验收，也未证明最初的辅助进程退出根因。更新后请重新加载插件；若宿主缓存旧模块，完全退出再打开宿主。手动确认显示／隐藏、视图切换、尺寸调整与原故障场景；没有自动提权、升级 WebView2、禁用 GPU 或清空用户缓存。
